## 4. 六条会决定搜索形态的结构性事实

1. **本地/平台差 11.9039pp**（本地 micro 72.8696% vs 平台 60.9657%），且**对 val 上任何指标结构性不可见**。
2. **迁移率（唯一跨域指标）**：FT **0.8366**、LT **0.8375**（= 平台分 / 本地分）。
3. **本地↔平台相关系数：官方文档里不存在。** 手上只有 2 个平台点，证据是**一强一弱**：
   - ①（强）初赛同批实验中本地 val 最高（**69.47%**）的候选平台**最差**（**59.89%**）；
   - ②（弱）复赛**只有 macro 一项排序反向**（本地 LT 71.8655 vs FT 71.8054，而平台 FT 更高，差 **30 张**）；**micro 是和平台一致的**（本地 FT 72.8696 > LT 72.6949，平台同向）。
   - 正确表述是「**不能可靠依赖本地排序**」，**不是**「本地完全没有信息」。30 张的差异不足以证明整体反相关。
4. **单种子噪声 0.90pp**（初赛实测：同配方两 seed 平台 61.21% vs 60.31%）。**复赛阶段所有候选（FT/LT/NPU/LoRA/V3 三点/搜索四点）全是单 seed 42，从未做过第二 seed 复验。**
5. **full-FT 这一族已贴自身天花板**：平台 FT/LT 只差 0.0801pp（30 张），本地全部差异落在噪声内；本地 train_accuracy 86.83% vs val micro 72.87%，泛化裂口 13.96pp，且 epoch 6→8 只 +0.16pp、学习率已退火到 1e-6 → 「单纯延长同一配方期望收益很低」。
6. **唯一一次真正的「换盆地」是 LP→FT**：池内 macro **+9.23pp**、micro +9.267pp，按 support 五分位均匀（**+7.97 ~ +9.99pp**），750 类中 560 好 / 162 平 / 28 差。**且该增益在第 2 个 epoch 就基本到位（69.29%）** —— 来自「解冻」这个动作本身，不是「学得更久」。

### 4.1 由上一条引出、必须点明的逻辑缺口（**这是本说明书最重要的单点**）

若假设两臂迁移率相同（0.8366），则 LP 平台分应约 **53.2%**，即 LP→FT 的 +9.23pp 本地增益换来了约 **+7.7pp 平台分**（60.97 vs ~53.2）。
**但这个推算默认了「两臂迁移率相同」—— 而那恰恰是从未验证过的前提**（RM-LP 从未上传，平台分为 null）。
⇒ 我们**并不知道那次大跃升究竟迁移了多少**。「大跃升能迁移」目前是**假设，不是事实**。
⇒ 它一旦被测出，能回答的是**这一个具体问题**：**「解冻」这一种改动的收益迁移了多少**。
⇒ **但它不能建立通用的换算函数。** `平台准确率 ÷ 本地准确率` 只是一个**描述性比值**，不是可迁移系数 —— 同样的本地增益，来自分辨率、标签修正或采样时，平台效应可能完全不同。因此 LP 探针的价值是**排除一种最坏的读法**（「本地改善只服务于同源识别」），而不是给出此后所有候选的排序依据。

## 6. **已实现、有校验分支、有单测，但 0 个 config 启用过**的机制（最大未开采区）

### 6.1 被 `trust` 闸门挡住的整套机制族

复赛主线的合规闸门 `rematch_assets.py` 里有一条硬禁止：**`trust.enabled` 必须为 false（"trust disabled in first round"）**，另有 `loss_reweighting == 'none'`、`balanced_softmax_tau == 0`、**任何 `loss.<x>` 子字典里 `enabled: true` 一律拒绝**。被这条挡住、**但代码/单测/CLI 全部齐全**的机制：

**⚠️ 关于「沉没资产」的两条重要限定（此前的优先级排序据此作废）**

**(1) 引用次数说明工程投入，不说明预期收益。** 不能因为某个模块引用多、单测全就把它排在前面。优先级应由「**与当前基座兼容、机制是否真未测、增量成本、监督来源可靠性**」决定。

**(2) 「只开一个开关、成本一次训练」并不普遍成立 —— 引用最多的那两个恰好不是现成开关。** 与当前基座（`full_finetune`）的兼容性实测：

| 机制 | 强制要求的前置条件 | 与当前 FT 基座的关系 |
|---|---|---|
| `trust.subspace_projection` | 要求 `trust.enabled` + **在线 `visual_lora`** + `loss.name=gce` + 强制 `feature_distillation_weight>0` + 与 11 个机制互斥 | **要换掉 FT 基座**（改为 LoRA）→ 不是零成本 |

**(3) 另有一条闸门细节会改变成本排序**：`rematch_assets.py:60-62`
```python
for key,value in config['loss'].items():
    if isinstance(value,dict):

```
即**任何 `loss.<x>.enabled: true` 一律被拒**。因此：

- ✅ **`double_softmax_cross_entropy`** 是 `loss.name` 的取值（`config.py:63` 枚举内、`trainer.py:1828` 已接线），**不受此闸门限制 → 真正的即插即用**；

## 7. 从未被触碰的结构性空白（不在任何 config 的维度里）

1. **全量 148,695 训练（+11% 数据）** —— 复赛现存数据里**唯一还没喂给模型的 11%**；同一阶段官方数据，规则上完全合法。RM-FULL 曾被取消，文档多轮写「不得自行启动」。**但当初取消的现实约束是算力，现在 NPU 单点约 34 分钟，算力约束已不成立。**
2. **超过 16 轮的训练** —— 复赛最长 16 轮。而**初赛团队最佳实践是 epoch 44**。本地「延长同配方收益低」的证据（+0.16pp/2 轮）是在 8 轮 schedule 下测的，**16→44 轮是一个从未测过的区间**。
3. **第二 seed 复验** —— 方法论明确要求「任何候选的收益声明必须在第二个 seed 上复验」，而**复赛所有候选全是单 seed 42**。当前 0.90pp 的噪声量级是从初赛借来的。
4. ~~**740/750 与 741/750 类别覆盖的根因**~~ → **已于 2026-09-23 完成，结论是「不是 bug」**。见 [类别覆盖与映射审计](rematch750_class_coverage_audit_20260923.md)。
   口径已钉死：740/741 是**测试集 37,444 张图上 `pred_results.csv` 出现过的不同标签数**（不是 val，也不是「判对过的类」）。映射 0..749 双射且与反向映射互逆、CSV 标签全在界内且与 test_manifest 完全一致、缺失类**散在非连续区块**、**竞争类别完全分散**、离线重建 `predicted_class_count` 精确复现 741。**映射类 bug 全部排除，本线关闭。**
   ⚠️ **「上限约 1.3pp」这句要收回**：`9/750 ≈ 1.2pp` 是**均衡测试下这 9 个类的理想类别质量占比**，**不是可以回收的分数**。审计确认：11 类并集里 7 类是训练样本 4–44 的极小类，**不存在可回收的 1.2pp**；也**不能**从无标签测试图去判断「测试集有训练集没有的类别」。**这项审计的价值是「排除一个 bug」，不是「捡回 1.2pp」—— 现已排除。**
   🔎 **审计的副产品（新事实，见审计 §6）**：test 的逐类预测分布对 val **强过度离散**（sd(z)=2.51、chi²/dof=6.32、246/750 类 |z|>2，极值 ±15）。两个无法区分的解释：测试集类别分布本就不同，或域漂移使预测塌缩到吸引子类。**只能作为诊断，不得用于调参**（RULE 禁止用测试集预测分布调参）。
5. **多尺度 + Flip TTA 从未走过正式提交链路** —— 已获组委会**书面裁定合规**，本地已实测正收益（见 §6.5），但被 `infer.py` 的首轮闸门挡住。这是一条**与训练正交、可叠加在一切成果之上、几乎免费**的增益。
6. ~~**`class_to_idx.json` 与测试集类别的对应关系**~~ —— **2026-09-23 审计判定为结构性不可核**：`test_manifest.csv` 的 label 列 37,444 行全为 `-1` 占位符，测试图名是扁平 md5，因此**无法在合规前提下**判断测试集是否含训练集没有的类。若测试集确有训练集没有的类，该类永不可预测 —— 但这属于**对测试集标签的推断**，规则禁止，**本线关闭，不再尝试**。

## 8. 我认为最关键的三个判断（供你反驳）

### 判断 1：现有搜索协议的目标函数与「能否换盆地」不匹配
队友 V4 预注册了 **82 个点**（A=GCE/mixup/randaug/cutmix、B=损失族、C=软修复与伪标签、D=锚点/解冻层/层衰减、E=长尾、F=输入分辨率、G=SAM、H=线性探针头），全部围绕**同一个 base**（batch1024 / 16 轮 / head_lr 4e-4 / backbone_lr 1.2e-5 / 锚点 2.0 / LP 初始化）**各改一个旋钮**。
其晋级门槛是 **`local_significant` = macro Δ≥+2.0pp 且 micro Δ≥+1.0pp**。
**三个具体问题**（注意：**不能说「单变量按设计就到不了 +2pp」** —— 一个变量也可能改变整个训练机制）：
1. **82 点共享同一个 base，容易遗漏交互**（例如「数据量 × 训练长度」这类交互，单变量网格结构上测不到）；
2. **用本地双门槛过滤全部平台提交，会系统性排除跨源改善** —— 而跨源改善恰恰是唯一真正重要的一类改善；
3. **已关闭方向、工程失败、真正未测方向被混在一起**（例：两个锚点下调点被记为「已关闭」，实为**未完成的测量**，见 §5.2）。

✅ 需你判断：门槛是**保留为「强本地信号」标签**（而非唯一入口），还是**改手段**（缩减 82 点为一个小批次），还是两者都做。

### 判断 2：在这种结构下，**信息**比**分数**更值钱
平台额度 2/天、整阶段只用了 2 次。在「只有 2 个平台点、且两次都排序反向」的条件下，**任何候选的本地读数都无法排序**。而**一次 LP 探针提交**能把 §4.1 那个缺口补上：给出**唯一一条本地→平台的换算函数**，此后所有决策才有依据。相比之下，把一个名额用在「本地 +0.2pp」的候选上，**买到的信息量接近于零**。
⚠️ 这与用户当前规则「只有出现显著本地跃升的 candidate 才占用平台提交」**存在直接张力**。我倾向认为该规则对「**方法候选**」是对的，但应给「**标定测量**」留一个例外。请你表态。

### 判断 3：未开采区里有真东西，但**「已实现」不等于「低成本可跑」**
§6 那张表的共同特征是：**代码写完了、单测过了、校验分支写了、然后 0 个 config**。这确实值得清点 —— 但**不能**据此认为「试跑成本 = 一次训练」：引用最多的两个（`subspace_projection`、`snscl`）**都强制要求换掉当前 `full_finetune` 基座**（详见 §6.1 的兼容性表），单测通过不等于复赛 FT 兼容、更不等于主线端到端跑过。
真正「即插即用」的只有 `double_softmax_cross_entropy`（`loss.name` 取值，不受 `loss.<x>.enabled` 闸门限制）；`adaptive_cap` 形式上是 `loss.adaptive_cap.enabled`，**会被闸门拒绝，需先改闸门**。
✅ 需你判断：其中哪些值得插队，以及**是否要先就「伪标签 / teacher-student」取得组委会答复**（注意：原标签下的损失截断**不属于**这一类，可直接做）。

# 11. GPT-6 的裁决与修订后的首批计划（2026-09-23 回复）

**GPT-6 拒绝的三个强推论**（本节据此修订，**已在上文对应位置改正**）：
1. ~~LP 能建立通用换算函数~~ → **不成立**。`平台÷本地` 是描述性比值，不是可迁移系数。LP 只回答「解冻这一种改动的收益迁移了多少」。（见 §4.1）

### 12.4.2 H1：本地增益与迁移率负相关 —— 它与 §11.3/批次 1 对 B 轴的建议**相反**

**H1**：在这个任务上，「本地 val 涨分」与「平台迁移」可能**负相关** —— 因为任何让模型更拟合训练来源的手段，都会同时抬高本地 val 并加深来源依赖。

若 H1 成立，则：「在 FT 家族内部找本地涨分」这条路**系统性无效**，而这正好解释为什么这么多轮本地提升（OOFW −0.13pp、FT94/LT06 融合 +0.08pp、Flip TTA +0.16~0.24pp）都没转化。

**它对 B 轴给出与批次 1 文档相反的预测**：去掉特征锚点 = 特征更自由地移动 = 更多 source fit = **本地会涨、平台会跌**。批次 1 当时写的是「约束越松 val 越好 → B 轴先验**上调**」，那是纯本地口径。

**两者必有一个错**，而队友在 NPU 上跑一次 B 轴就能判。因此 B 轴的正确定位是**负向检验**（跑它为了看「本地涨了平台是否反而跌」），而不是提分候选 —— 这比它当提分候选有价值得多。

**我方立场**：H1 是**假设，不是结论**，且与 §十（特征漂移分析）的乐观读法存在张力 —— 那次测量支持「FT 的增益是真实表征改善、更可能迁移」，而 H1 说的是**边际**变化（+X 本地 pp 能换来多少平台 pp）不按同比例走。两者可并存，但**需要 GPT-6 判断 H1 值不值得用名额去证伪**。

### 12.4.3 val 过度离散对照：唯一可能造出「本地跨源代理」的零 GPU 测量

T0 的副产品（test 逐类预测分布对 val **强过度离散**）当时因规则无法区分两种解释：①测试集类别分布本就不同 ②域漂移把预测**塌缩到吸引子类**。

**这个可以直接判，零 GPU**：把同一统计量算在 **val** 上 —— 用**没训过 val** 的 dev RM-FT / RM-LP checkpoint 的 val 预测，对照 val 的真实类别 support。

- 若 val **同样强过度离散** → 塌缩是**模型固有属性**，与来源无关 → 解释②关闭，**不存在本地跨源代理**。
- 若 val **离散正常**、只有 test 离散 → 域漂移**确实改变了预测几何** → 这是**第一个能本地观测到两个来源差异的量**。

第二种情况价值极大：本项目全部困境的根因是「**没有任何本地指标能预测平台**」（11.90pp 对 val 上一切指标结构性不可见）。而用 val 统计量做模型选择**不碰测试集分布**，规则上合法。

**我方判断：这是当前性价比最高的零 GPU 测量，建议列为下一项 T0。**

### 12.4.4 D 轴（训练侧成像退化）在 V4 里是空的，且其判据必须是**反向**的

我方已**逐份核对** V4 的 A 组（A01–A10）：`mixup` / `soft_CE_mixup` / `cutmix` / `RandAugment` —— **全部是光度+几何增广，没有任何成像退化**（JPEG 量化、模糊、噪声）。所以 D 轴不重复队友的工作。

D 轴是唯一有**机制故事**直接攻 11.90pp 的方向：让模型不依赖**来源特有的成像统计**。而它的**期望签名是本地小跌** —— 用一点 in-domain 拟合换 source 不变性。**若按「本地涨分」筛，这条轴会被自己的判据杀掉。**

### 12.4.5 多种子复现现在免费 —— 应先修掉最大的测量缺陷

本项目历史上**所有**结论都落在单种子 **0.90pp** 噪声内：

| 结论 | 效应量 | seed 数 |
|---|---|---|
| A1 vs 对照 | −0.36pp | 1 |
| OOFW vs 对照 | −0.13pp | 1 |
| FT vs LT（平台） | 0.080pp | 1 |
| **V3 vs FT（「是否值得取代 RM-FT」的全部依据）** | **+0.44pp** | **1** |

并行 NPU 下，每点跑 **3 seeds 不增加 wall-clock**。**我方建议把「3 seed 配对、效应需大于噪声才叫结论」定为新默认判据** —— 这比再多跑 20 个点位有价值。
