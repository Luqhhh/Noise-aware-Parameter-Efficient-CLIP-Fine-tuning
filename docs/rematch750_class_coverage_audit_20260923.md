| 问题 | 结论 |

| 740/741 的口径 | **测试集 37,444 张图上 `pred_results.csv` 出现过的不同标签数**；对应 RM-LP / RM-FT seed42 两个 checkpoint |
| 映射是否一一对应 | **是**。class_to_idx 0..749 双射且与 idx_to_class 互逆；CSV 标签全部在界内、格式正确、与 test_manifest 完全一致 |

**总判定：`9–10 个类从未被预测`不是 bug，是长尾 + 分布差异。** 这一条线可以关闭，不必再投入算力。

## 2. 口径：740/741 到底统计的是什么

**出处已定位到代码**：`aegis_clip/cli/analyze_feature_drift.py` 的 finding_2，方法原文是
「per-image comparison of the two pred_results.csv over 37444 test images」。
所以 `classes_used: {RM_LP: 740, RM_FT: 741}` 是——

> **测试集 37,444 张图上，每份 `pred_results.csv` 里出现过的不同预测标签数。**

**不是** val 上的统计，**也不是**「判对过的类」（测试集没有标签）。
容易混淆的是 `evaluation.py:137` 有一个同名字段，那个统计的是 **val**：

| 集合 | RM_LP | RM_FT |
|---|---:|---:|
| **val**（14,880 张，`evaluation.py:137`） | **741** | **745** |
| **test**（37,444 张，本审计） | **740** | **741** |

test 的图数是 val 的 **2.52 倍**，覆盖类数却**更少**。这个反直觉的对比是 GPT-6 要求「立刻做」这条审计的直接动机，其成因见 §6。

两臂 CSV 均为本机重建、可校验：

| 臂 | csv sha256（前 12） | 行数 |
|---|---|---:|
| RM_LP | `5d564b6d96cf` | 37,444 |
| RM_FT | `7e390c533883` | 37,444 |

## 4. 未预测类别

| 集合 | 从未被预测的类数 |
|---|---:|
| RM_LP 在 test | 10 |
| RM_FT 在 test | 9 |
| RM_LP 在 val | 9 |
| **并集** | **11**：19, 46, 58, 183, 274, 305, 407, 413, 550, 589, 671 |

**关键判据：并集不是连续区块**（散在 19…671）→ 排除**分类头截断 / 标签编号偏移**。
（若是偏移或截断，缺失类必然连成一段。）

差异是**双向**的，不是单向丢失：

- **7 类**在 val 与 test 上**都**从未被预测：19, 46, 183, 305, 413, 589, 671
  —— 训练样本 4~44、val 样本 1~5、val 召回 **0.0**。**纯长尾，完全可解释。**
- **2 类**在 val 上从未预测、在 test 上却出现了：**114（20 次）、324（17 次）**
- **3 类**在 val 上预测过、test 上从未出现：58、274、407

### 4.1 竞争类别：完全分散

在 val 上，这些类的样本被预测成了什么（test 无标签，不可算）：

| 类 | val 样本 | 自身命中 | 最高分竞争类 |
|---:|---:|---:|---|
| 19 | 3 | 0 | 235, 372, 506（各 1） |
| 305 | 3 | 0 | 17, 544, 287（各 1） |
| 671 | 4 | 0 | 471, 310, 106, 300（各 1） |
| 589 | 5 | 0 | 224(2), 59, 683 |
| 274 | 16 | 5 | 448(2), 412, 278 |

**没有出现集中的竞争类。** 这正是「模型根本认不出这个类」的签名；
若是**映射 / 重名 / 标签互换**类缺陷，竞争类会高度集中到某一个固定类上。这一条独立地把映射类 bug 排除掉。

## 5. 分类头行 / 异常样本读取 / 编号偏移

用**离线重建**做硬校验：RM-LP 是 `peft_mode: frozen`，可训练参数仅
`classifier.weight/bias`（384,750），因此把缓存的冻结特征乘上线性头就能**完全离线复现**它的 val 预测（纯 CPU）。

| 锚点 | 重建值 | 记录值 | 差 |
|---|---|---|---|
| `predicted_class_count` | **741** | 741 | **精确一致** |
| `raw_micro` | 0.6362231373786926 | 0.6363575458526611 | **2 张 / 14,880 = 0.013pp** |

2 张之差落在**数值并列敏感度**内：全 val **无精确并列**（最小 top1−top2 logit gap = 2.8e-4），
但 gap ≤ 1e-3 的有 12 张、≤ 1e-2 的有 105 张。分类头**没有缺行**，样本读取正常，编号无偏移。

## 6. 附带发现：test 的逐类预测分布对 val 强过度离散 ⚠️

这是本次审计**真正的新信息**，且不属于原问题。

设 `k = 37444 / 14880 = 2.5164`。若测试集是同分布 iid 抽样，则
`z_c = (Y_c/k − X_c) / sqrt(X_c·(1 + 1/k))` 应服从 N(0,1)，其中 X = val 逐类预测次数，Y = test 逐类预测次数。

| 统计量 | 实测 | 同分布假设下期望 |
|---|---:|---:|
| sd(z) | **2.51** | 1.0 |
| chi²/dof | **6.32** | ~1 |
| \|z\|>2 的类数 | **244** | ~34 |
| \|z\|>3 的类数 | **110** | ~2 |

极值举例（val 次数 → test 次数）：

| 类 | 训练样本 | val | test | z |
|---:|---:|---:|---:|---:|
| 265 | 204 | 2 | **68** | +14.97 |
| 679 | 137 | 17 | **224** | +14.78 |
| 648 | 197 | 19 | **234** | +14.36 |
| 741 | 149 | 7 | **112** | +11.99 |
| 450 | 218 | 31 | **254** | +10.63 |
| 523 | 193 | 25 | 2 | −4.10 |
| 274 | 143 | 16 | **0** | −3.38 |

**解读（两个解释无法用现有数据区分，且都不需要区分）**：

1. **测试集真实的类别分布本身与训练池不同**（更集中）；
2. 测试集类别分布相同，但**域漂移使预测塌缩到少数「吸引子」类**。

两者都导向同一结论：**val 上逐类的预测倾向不是 test 上逐类行为的可靠代理。**
注意这不是抽样噪声 —— chi²/dof 6.32、sd(z) 2.51 的量级远超噪声。

**与已知结论的关系**：
- 它给「不能可靠依赖本地排序」补上了**逐类的量级**（246/750 类的 |z|>2，最极端 ±15），
  而不是只停留在「30 张图的宏观反转」。
- 它与既有测量**不冲突**：推理侧几何探针已证明 11.90pp 差距**不是输入几何**造成的；
  本审计说明该差距在**类别维度上是有结构的**。
- 它**不**改变任何已定判据，也**不**产生新候选。理由见下。

### 6.1 为什么这条不能拿来调参

RULE 明令禁止用测试集预测分布调参。本审计的 Y 正是测试集预测分布。
因此该结果只能作为**已完成工作的诊断记录**：解释「为什么 val macro 的提升不必然迁移」
（macro 是 750 类等权平均，而 val 的逐类权重结构与 test 差得远），
**不得**用于选点、设阈值、加权或派生任何候选。
