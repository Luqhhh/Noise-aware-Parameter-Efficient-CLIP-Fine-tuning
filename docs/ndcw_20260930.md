## 工程与统计口径

- `analysis/near_duplicates/` 提供用户指定的五个脚本入口；主实现为
  `reproducibility/aegis_f1/ndcw/`，统一 CLI 为 `python3 -m ndcw.cli`。
- `configs/v2_ndcw/audit.yaml` 固定 k=10、0.94 起始相似度与 0.005 步长；
  另外四份训练 YAML 与现役 V2 逐项相同，prepare 时拒绝 LR、增强、采样等漂移。
- 复用已审计的当前阶段 OpenAI official frozen CLIP ViT-B/32 224 中心视图缓存。
  沿用现有 v1 的分块精确 kNN 方法，只排除 self，保留 exact 候选作独立统计。
  精确检索仍有 O(N²) 计算；不生成 N² pair 表，tile 内存有界、近邻存储 O(Nk)。
  相似度并列按原始索引固定排序。A0 仅 CPU 两线程，检索上限 7200秒，
  感知核验上限 1800秒，超时停止，没有后台续跑。
- 本机没有 PyArrow/FAISS，不改共享环境；pair 表使用无损 `pair_candidates.csv.gz`
  与 `verified_pairs.csv.gz`，替代建议的 Parquet。只保留 ≥0.94 的 top10 候选，
  非 exact 和跨标签计数分别报告，exact 总量从完整官方 content_group 表计算，
  不受 top10 截断影响。
- 感知核验使用整图 pHash（64bit，DC置零）与 RGB 16×16 thumbnail：
  Hamming≤6、RMSE≤0.10、|log宽高比|≤0.08、灰度标准差≥0.03 同时通过。
  这些是首版固定工程规则，不是实测最佳阈值；失败图片不通过核验。
  只解码非 exact 候选涉及的官方训练图，先核对原文件 SHA256，不解码/打开 test 资产。
- A0 报告保存整个阈值曲线及同阶段输入/源码 SHA256。完成曲线后从该网格选择
  `t_medium≤t_strong`，必须附证据理由；`frozen_thresholds.json` 排他写入，
  同一审计不能换输出目录再调阈值。训练/平台结果不参与选阈值。
- Strong=跨标签、non-exact、≥t_strong、mutual top10、感知通过；Medium=跨标签、
  non-exact、≥t_medium、mutual/感知至少一项。Weak/同标签/exact 权重1。
  样本取所有有效边的最小权重：Strong=.2、Medium=.5，不累乘。
  连通分量仅用于 median/largest cluster 诊断，不传播权重。
- 每类按 level、感知支持、mutual、相似度降序保留最强样本，同分按路径排序；
  放不进0.10×类别样本数预算的样本完整恢复1，不改成新的连续权重。
  `raw_nd_level/raw_nd_weight` 保留 cap 前证据，reason 记录恢复原因。
  报告实际 affected rate 与等效监督损失率，后者才是10%上限。
- 全训练与 dev 分别生成 `ndcw_weights.csv`、`ndcw_dev_weights.csv`，两者覆盖
  全部148,695行。Dev只允许两端均在train_dev的边决定权重，val_dev行保持1，
  cap按133,815训练子集类别计数；full按全部训练图计算，不删除任何图。
  检索候选和 mutual 来自全官方训练缓存，dev采用其内部边的保守子集。
  固定split不变；另外记录跨split冲突边和关联val图数量，作为本地外推的限制。
- 联证使用已校验的P0逐样本表和本轮V1 targets。V1 low trust定义为 CL 未保留
  原标签（`kept=False`），并报告其连续训练 weight；这不等于错标。
  已有 OOF 表只有 centroid/ridge 折外预测，没有 `p(original label)`，概率保留null；
  不重新拟合OOF或把in-sample概率冒充OOF。可显式接入同阶段绑定的已存在概率表。
  trusted-val为预ND的P0 weak-consistent且snapshot-confidence通过的代理，不能称干净真值。
- Gate A：raw冲突≥ceil(0.005N)，full为744；Gate B：raw冲突≥50类；
  Gate C：已知high-trust冲突足以排除“>95%已被低trust捕获”。
  V1没有val_dev trust，报告已知覆盖率和low-trust比例区间，未知全部计为低trust的
  上界也必须≤95%，不补造验证trust。Full/dev两套门都要通过；另外要求 cap 后
  仍覆盖0.5%与50类，避免cap消灭了实际干预。失败/缺证据时关闭或保留未知，不开训。

## V2 接入与配对判断

`prepare-pair`生成独立control/treatment目录、recipe、V2 plan与绑定配置。
Control加载全1 sidecar。Sampler始终使用原标签类别频次的inverse-sqrt，
ND权重仅进入loss。普通批次为 ΣwᵢLᵢ/Σwᵢ；Mixup/CutMix先对原目标乘原样本权重，
再沿原混合操作组合两端贡献，整逻辑批次统一除以原权重总和。
Micro batch不各自归一化。全1批次走原来的数值路径。
记录每轮抽样轨迹摘要；配对报告拒绝抽样顺序或有效训练配置不同的两臂。

Probe沿用V2的3–10次逻辑更新、完整raw/EMA holdout评估与成本记录；
逐步记录loss、gradient norm、weight sum、effective batch size与实际降权样本数。
配对probe固定使用末次EMA（不按probe分选择raw/EMA）；非有限loss/梯度立即停止。
至少实际观察到一次降权且tail宏观差值>−2pp，才产生`probe_pass`。
正式N1授权必须绑定该报告及当前plan，再沿用V2现有有限时长与实测成本校验。
Probe不保留候选模型，也不推理test。

N1按原V2选择各臂单份checkpoint，输出全量逐张修正/退化与每类指标，以及：
macro、micro、固定tail-10% macro、remaining-90% macro、trusted-val macro/micro、
affected-class macro、unaffected-class macro。Tail按train_dev频次最低75类冻结，
affected按dev cap后实际降权类别冻结，验证代理在候选产生前冻结。
差值统一使用个百分点。四个门同时成立才返回`n1_pass_checkpoint`：
macro≥+0.20pp、trusted_macro>0、tail_macro>−0.30pp、affected_macro>0。
缺失slice不通过门；失败返回`close_ndcw`。通过也不自动启动448/576/full。
