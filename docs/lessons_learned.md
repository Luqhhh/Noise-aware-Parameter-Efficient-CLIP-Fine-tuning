# 经验与方法论教训

本文件提炼自上一阶段（初赛，500 类 / 约 103K 训练图）跑过的数十轮实验，目的是让后来者**不必重走弯路**。

除特别说明外，数字均为该阶段的平台实测成绩；阶段相关的绝对分数不具跨阶段可比性，**可迁移的是方法与陷阱**。

---

## 一、陷阱：会让人得出错误结论的东西

这一节最重要。以下每一条都是真实踩过的坑，且都曾一度产生过看起来很有说服力、但完全错误的结论。

### 1. 本地验证分数不能预测平台成绩，甚至可能反相关

同批次实验中，**本地 val 最高（69.47%）的候选平台最差（59.89%）**。

**Why**：验证集与训练集存在重叠、且验证标签本身含噪，本地指标衡量的是"记住了多少"而非"泛化多好"。

**How to apply**：平台实测是候选晋级的**唯一**标准。本地指标只用于安全审计、复现检查和工程止损（−2pp），**不设本地晋级门槛**。

### 2. 单 seed 结果不可靠

同一配置两个 seed 的平台 TTA：**61.21% vs 60.31%，差 0.90pp** —— 远大于大多数实验声称的增益。

**How to apply**：任何候选的收益声明必须在**第二个 seed** 上复验。只跑一个 seed 的"改进"基本是噪声。

### 3. Split 谱系不一致会伪造巨大的假信号

父模型与子模型使用了不同的 train/val 划分时，本地 raw_micro 从真实的 **69.43% 假胀到 79.22%（+8.5pp）**。

**How to apply**：验证必须与训练使用**同一份 split**。修复后 epoch-0 baseline 精确匹配 —— 这是判断谱系是否对齐的有效自检手段。任何时候看到异常大的本地增益，先查 split。

### 4. 验证集混进训练集会污染一切基于验证的诊断

某次冻结 prior 的拟合只带来约 0 的收益，根因是 `final_full_train.csv`（103,218 行）**包含了全部 10,316 行验证样本** —— prior 是在模型已经记住的样本上拟合的。

**How to apply**：做全量训练时，明确区分"用于选 checkpoint 的验证集"与"全量训练集"。全量训练后原验证集只能称为**重叠诊断**，不能再用于挑选 checkpoint。

### 5. 数值协议不一致会让"完全相同的推理"产生不同结果

同一模型、同一权重、同一超参，仅因一处 `torch.backends.cudnn.allow_tf32` 的差异，24,967 行预测中有 **32 行不同**；重放校验因此按守卫停止。

**How to apply**：声称"重放"时必须固定全部数值开关。把推理的数值环境（TF32、AMP、确定性开关）作为协议身份的一部分显式登记。

### 6. 用 `repr()` 当哈希身份会导致校验永远失败

某次合规门禁把 `repr(preprocess)` 纳入协议哈希，而其中嵌入了 CLIP `_convert_image_to_rgb` 的**堆地址** —— 拟合进程与应用进程算出的哈希必然不同，该门禁**按构造就永远无法通过**。

**How to apply**：任何参与哈希或相等比较的对象，先做**规范化**（剔除地址、内存相关表示），再序列化。

### 7. 本地调参会在测试集上过拟合"协议"，即使没碰测试数据

拟合在测试批统计量上的 prior 曾拿到阶段的绝对最高分，但它属于**不同来源协议**，与其他结果不可比，并留下了未决的合规问题。

**How to apply**：任何使用测试集统计量的步骤都要显式登记、单独分组、不与合规结果混排。别让它悄悄成为"基线"。

## 二、被验证有效的方向

- **全微调父模型 ← LoRA 父模型的迁移**：从 LoRA 自训练父模型迁移到全微调父模型带来 **+0.50pp 级**平台增益（69.08% → 69.58%）。
- **attention-local / global 概率融合**：该阶段最强的跨模型信号，相对纯 Flip TTA 有稳定提升。
- **高精度清洗样本**：见下节。
- **LoRA 增益的稳定性**：双 seed 下 Bare 仅差 0.01pp（60.65% vs 60.64%），说明 LoRA 带来的增益本身是真实的、可复现的。
- **特征缓存**：一次性编码全量训练集（约 30 分钟），此后训练直接读 `[B,512]` 特征（约 3s/epoch，对比在线编码约 140s/epoch）。缓存的构建时间在几轮实验内即可收回。
- **判别式学习率**：head 与 backbone 使用不同 LR，并保持全程比例恒定的 LambdaLR。

## 三、被证伪 / 已关闭的方向

**数据层面：**

- **数据增强在该任务上无正面收益**。A0（无增强）69.86% 为最佳；A1（RRC + Flip）在匹配学习率后 69.77%，Δ=−0.09pp；A2（+ColorJitter）67.36%，**ColorJitter 显著破坏细粒度判别信息**。
- **删除 > 重标**。重标 100 个样本（0.1%）反而 **−0.42pp**；当时 OOF 预测准确率约 69%，不足以支撑可靠重标。**当你确定标签错了、但不确定正确答案时，删除比重标安全。**
- **清洗的精度 > 覆盖面**。删 991 个高精度样本（+0.90pp）> 删 6354 个中精度 > 删 8680 个低精度（−0.76pp）。精度碾压数量。
- **跨类别重复图片是真实存在的**：扫描发现 1,032 组跨类别 SHA-256 完全重复，涉及 2,095 张图（2.0%）—— 同一张图进入 2–4 个不同类别目录，监督彼此矛盾。处理方式是 CLIP 特征质心仲裁去重。

**模型/推理层面：**

- **Linear head 远优于 Cosine head**：69.86% vs 63.61%，差距约 6pp。
- **更多视图不等于更好**：三视图互补融合 62.03%，低于纯 attention-local/global 的 62.67%（−0.65pp）。带噪的本地排序不能代替平台验证。
- **数字类别不能继承语义 prompt 的鲁棒性**：固定数字 prompt 的 raw / clean-core 仅 0.23%，500 个文本方向的 90% 能量秩为 1。按语义 prompt 的经验去设计数字类别的文本侧方案是无效的。

**已关闭的完整方向清单**：Dropout、ColorJitter / RandomErasing、Cosine Head、Label Smoothing、Head EMA、EMA Loss、Prototype Weighting、CE 下部分解冻、Head-only EMA Teacher + Consistency、GCE q=0.9、4-view TTA、vertical flip、OOF 3-tier discrete weight、OOF relabel / pseudo-label、Classwise CL-only drop、ELR、PEFT LN-tune、半监督回收，以及结构化 Head、同轨迹 checkpoint averaging、Clean-Routed LoRA、Trusted Prototype-Contrastive、Dynamic Trust Refresh。

## 四、门槛纪律

项目内部自设三道门槛，**贯穿所有实验**：

| 门槛 | 值 | 含义 |
|---|---|---|
| 迭代投资回报门 | **+0.30pp** | 相对当前胜者的提升不到此值，该轮**关闭**，不派生参数扫描 |
| 本地止损 | **−2pp** | 本地工程诊断跌破即停止 |
| 筛选晋级门 | **+0.20pp** | 初筛通过所需 |

**实际效果**：一轮典型实验的增益在 **0.02–0.09pp** 量级，绝大多数轮次都在"未达门槛、关闭"的判定下结束。这些轮次的价值在于**排除**而非得分。

**关键纪律**：
- 未达门槛就关闭，**不自动派生**强度扫描 / 正则扫描 / 边界扫描
- 每轮都是相对上一轮胜者的**单变量**改动，训练预算固定（如 3 个 sample epoch）
- 一轮的结论不能越界解释为"该机制无效"——只能说"在该配置下未达门槛"
- 方案**预注册**：固定的候选、门槛与止损规则在开跑前写好，跑完不得回改

## 五、工程实践

- **预注册 + 只读 preflight**：每轮先做只读资产核对（checkpoint、清单、哈希、映射、内容组），核对失败即停，不进入 GPU 阶段。多数自动化队列默认只读，需显式 `--execute` 才落盘。
- **共同对照（common-control）**：A/B 两组的首 batch、增强、soft target、权重、logits、anchor 必须逐项对齐验证，否则差值不可归因。
- **哈希绑定一切**：checkpoint、配置、映射、代码快照、CSV/ZIP 全部登记 SHA-256，ZIP 内外 CSV 必须字节一致。
- **审计闸**：合规检查（如 TTA、本地视图、均衡 prior）以显式 `--acknowledge-*-risk` 参数留痕，使"我知道这里有权衡"成为可追溯的记录。
- **数据资产严格解码**：按 Pillow 严格像素解码全量图片，记录失败数；不允许 truncated-image 宽容读取或占位图预测。
- **内容分组防泄漏**：按解码像素 + 尺寸 SHA-256 分组，训练与验证的**内容组交集必须为空**，防止同一图片的不同副本跨折泄漏。
- **产物目录隔离**：每轮输出到独立目录，避免跨实验污染。
